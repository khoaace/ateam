## 01 cách hoạt động

Bạn giao mục tiêu. Đội chia việc, làm, tự kiểm tra.

ateam không thay CLI bạn đang dùng — nó cho các CLI làm việc cùng nhau trên một bảng việc chung, và giữ bạn ở vị trí người quyết định.

  1. Giao mục tiêu

    Gõ như viết ticket: kết quả cần có và cách kiểm tra. Còn mơ hồ thì /grill để trưởng nhóm hỏi lại từng câu.

  2. Trưởng nhóm lập kế hoạch

    Chia thành task, chọn agent hợp việc, thứ tự phụ thuộc và effort cho từng task.

  3. Bạn duyệt

    Đổi người làm, sửa nội dung, bỏ task nháp, rồi F2 để chạy.

  4. Các agent làm song song

    Mỗi task một nhánh riêng. Agent có thể giao phần việc hợp với thành viên khác, hoặc dừng lại hỏi bạn.

  5. Tự kiểm tra

    Sau mỗi task chạy lệnh test của dự án; fail thì tự giao sửa kèm log lỗi.

  6. Review & merge

    Bạn xem diff rồi merge; trưởng nhóm review lần cuối, còn thiếu thì giao thêm.

## 03 tính năng

Mọi thứ cần có khi để nhiều agent cùng làm một repo.

Có cả trong terminal lẫn ateam web — cùng bảng việc, cùng lệnh /…, cùng cấu hình.

điều phối

  • Trưởng nhóm thật sự — lập kế hoạch, chọn agent hợp việc, review kết quả và giao thêm khi còn thiếu, tối đa 3 vòng.
  • Song song theo phụ thuộc — có giới hạn số task cùng lúc; agent tự giao phần việc hợp với thành viên khác.
  • Agent hỏi lại thay vì đoán — gặp chỗ mơ hồ, agent dừng hỏi bạn rồi làm tiếp đúng phiên.
  • Workflow dựng sẵn — thiết kế → code → test, hoặc mô tả bằng lời để trưởng nhóm dựng các bước.
  • Nhớ ngữ cảnh, đỡ token — /retry, vòng sửa test, /continue tiếp tục đúng phiên CLI; /init viết tổng quan dự án một lần.

an toàn & kiểm soát

  • Worktree & duyệt diff — mỗi task một nhánh riêng, không giẫm chân nhau; bạn merge hoặc trả lại.
  • Tự test, fail thì tự sửa — /verify npm test một lần; task làm hỏng test được giao sửa kèm log lỗi.
  • Hết hạn mức? Đổi người — nhận diện rate limit của từng CLI, cho nghỉ đến giờ hồi, chuyển task sang agent dự phòng.
  • Rule cho cả đội — /rules gửi kèm mọi prompt, agent nào cũng nhận; quyền shell / mạng của agent tắt mặc định.
  • Model & effort từng việc — /model claude opus, hoặc /task codex@xhigh … cho riêng một việc khó.

công cụ trong app

  • Code — editor phím vim, command palette, tìm & thay toàn dự án.
  • Git — stage, commit (AI viết message), nhánh, pull/push, stash, lịch sử, revert.
  • Lưới & chat — CLI thật của nhiều agent cạnh nhau; chat riêng từng agent, giữ phiên.
  • Terminal — !yarn dev chạy ngay trong app, gợi ý script từ package.json / Makefile, bắt port.
  • To-do, ghi chú, @file, dán ảnh — @ nhắc file theo cú pháp từng CLI, Ctrl+V dán ảnh chụp màn hình.

từ xa & theo dõi

  • ateam web — đủ chức năng như terminal; mở nhiều tab không chạy trùng task.
  • Từ điện thoại — --tunnel: Cloudflare Tunnel https + mã QR, bảo vệ bằng token, có chế độ chỉ xem.
  • Thống kê — token và cost thật từ log phiên CLI, lịch sử mục tiêu, hạn mức còn lại.
  • Thông báo — macOS / trình duyệt khi có việc chờ duyệt hoặc task lỗi.
  • 21 theme · Việt / English — theme tối, sáng, màu nhấn tuỳ chọn; /lang en đổi toàn bộ giao diện.

## 08 cấu hình

Mặc định hợp lý, chỉnh được mọi thứ.

File chung ở ~/.config/ateam/config.toml; mỗi dự án ghi đè bằng .ateam/config.toml (ateam init --project).

# chạy song song an toàn: mỗi task một nhánh, chờ bạn duyệt
isolation = "worktree"
merge = "review"

[verify]
command = "npm test"
max_fix_attempts = 2

[agents.codex]
effort   = "high"
fallback = ["claude"]
role     = "Viết code, sửa bug, chạy test, refactor."

# thêm bất kỳ CLI headless nào
[agents.gemini]
command    = ["gemini", "--yolo", "-p", "{prompt}"]
model_args = ["--model", "{model}"]
role       = "Đọc codebase lớn, viết tài liệu."

## 09 hỏi đáp

Câu hỏi thường gặp.

Có tốn thêm tiền hay cần API key không?

Không. ateam gọi đúng các CLI bạn đã cài và đăng nhập (Claude Code, Codex, Antigravity, Grok, OpenCode…), nên dùng gói đăng ký sẵn có của từng CLI. ateam không gửi dữ liệu đi đâu khác.

Hỗ trợ những CLI nào?

Có sẵn: claude, codex, agy (Antigravity), grok, opencode. Ngoài ra bất kỳ CLI nào có chế độ headless (nhận prompt, in kết quả ra stdout) — Gemini CLI, Cursor CLI, Aider… — thêm ở tab Agents, có mẫu và xem trước lệnh.

Agent sửa code của tôi có an toàn không?

Bật isolation = "worktree" và merge = "review": mỗi task làm trên một nhánh git riêng, không đụng thư mục làm việc của bạn; chỉ khi bạn duyệt diff và bấm merge thì thay đổi mới vào nhánh của bạn. Quyền chạy lệnh shell / dùng mạng của agent tắt mặc định, bật ở bước An toàn của /setup.

Muốn mọi agent làm theo quy ước của dự án thì sao?

Thêm rule bằng /rules (vd "commit message tiếng Việt", "không sửa file trong dist/"): ateam gửi kèm ở đầu mọi prompt, nên claude, codex, agy, grok, opencode hay agent tuỳ chỉnh đều nhận. Rule lưu riêng trên máy bạn, không vào repo. AGENTS.md / CLAUDE.md có sẵn trong repo vẫn được các CLI tự đọc như bình thường.

Dữ liệu nằm ở đâu?

Bảng việc, log, ảnh dán vào nằm trong .ateam/ của dự án (tự thêm vào .gitignore). Cấu hình chung, to-do và ghi chú ở ~/.config/ateam/. Mọi thứ chạy trên máy bạn.

Khi một agent hết hạn mức thì sao?

ateam nhận ra thông báo rate limit của từng CLI, đoán giờ hồi, cho agent đó nghỉ và chuyển task sang agent dự phòng (fallback) — kể cả vai trưởng nhóm. Xem tình hình bằng /usage; tự cho nghỉ bằng /cooldown.

Giao diện web có an toàn không? Mở từ máy khác được không?

Mặc định ateam web chỉ nghe 127.0.0.1 và từ chối yêu cầu có Host/Origin lạ; file ngoài thư mục dự án không mở được. Mở từ điện thoại: ateam web --tunnel (Cloudflare Tunnel, https) hoặc --host 0.0.0.0 trong LAN — khi đó mọi truy cập cần token (quét mã QR in ở terminal), có --readonly để chỉ xem.

Chạy trên Windows được không?

ateam được phát triển và kiểm thử trên macOS và Linux (Python 3.9 trở lên). Trên Windows, chạy trong WSL là cách gần nhất; bản Windows gốc chưa được kiểm thử.

Giao diện có tiếng Anh không?

Có. /lang en trong app (app tự mở lại), hoặc ateam lang en / ateam --lang en …. Lần đầu dùng, ngôn ngữ theo LANG của máy.

Có gì đó không chạy — bắt đầu từ đâu?

Chạy ateam doctor, rồi ateam log <số task>: dòng đầu ghi agent, model, effort và thư mục làm việc. Các lỗi hay gặp và cách xử lý nằm ở mục Xử lý sự cố trong README.
