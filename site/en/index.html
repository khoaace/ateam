## 01 how it works

You set the goal. The team splits it, builds it, checks it.

ateam doesn't replace the CLIs you use — it gets them working together on one shared task board, and keeps you as the one who decides.

  1. Give a goal

    Write it like a ticket: the outcome and how to verify it. Still fuzzy? /grill lets the lead interview you first.

  2. The lead plans

    Splits it into tasks, picks the right agent for each, sets dependencies and effort.

  3. You approve

    Reassign, edit, drop draft tasks — then press F2 to run.

  4. Agents work in parallel

    One branch per task. Agents can hand a part to a teammate, or stop and ask you.

  5. Automatic checks

    Your test command runs after each task; failures go back for a fix with the error log attached.

  6. Review & merge

    You read the diff and merge; the lead does a final review and adds tasks if anything is missing.

## 03 features

Everything you need when several agents share one repo.

All of it in the terminal and in ateam web — same board, same /… commands, same config.

orchestration

  • A real lead — plans, picks the right agent, reviews results and adds work when something is missing, up to 3 rounds.
  • Parallel, dependency-aware — with a concurrency limit; agents can delegate a part to a better-suited teammate.
  • Agents ask instead of guessing — on ambiguity an agent pauses to ask you, then resumes the same session.
  • Workflows — design → ⏸ your approval → code → review; describe one in words for the lead to draft, or save a finished goal as a workflow.
  • 🧩 Shared skills — one skill library for every CLI; the lead attaches them to tasks, $skill-name calls one directly.
  • Keeps context, saves tokens — /retry, test-fix rounds and /continue resume the same CLI session; /init writes a project overview once.

safety & control

  • Worktrees & diff review — one branch per task, no stepping on each other; you merge or send back.
  • Tests run, failures get fixed — set /verify npm test once; a task that breaks tests is sent back with the log.
  • Rate-limited? Hand off — detects each CLI's rate-limit messages, rests the agent until reset, moves tasks to a fallback.
  • Team rules — /rules are sent with every prompt to every agent; shell / network access is off by default.
  • Model & effort per task — /model claude opus, or /task codex@xhigh … for one hard task.

built-in tools

  • Code — vim-key editor, breadcrumb, command palette, search & replace; Source Control with an editable side-by-side diff.
  • Git — stage, commit (AI-written messages), branches, pull/push, stash, history, revert.
  • Grid & chat — several agents' real CLIs side by side; chat with any agent in its own session.
  • Terminal — real interactive shells (vim, htop, ssh), even in a task's worktree; !yarn dev with an in-place ■ stop, port detection.
  • To-do, notes, @file, image paste — @ mentions files in each CLI's syntax, Ctrl+V pastes screenshots.

remote & insight

  • ateam web — everything the terminal does; multiple tabs never run a task twice.
  • From your phone — --tunnel: Cloudflare Tunnel over https + QR code, token-protected, with a read-only mode; or hit ↻ in the 📱 popup to restart in remote mode.
  • Usage & quota — real tokens and cost from CLI session logs, goal history; 5h / weekly quota in the sidebar, as rings when it's collapsed.
  • Notifications & updates — macOS / browser alerts when something awaits review or a task fails; new versions are announced, /update installs and restarts.
  • 21 themes · English / Tiếng Việt — dark, light, custom accent; /lang vi switches the whole UI.

## 08 config

Sensible defaults. Everything adjustable.

Global config lives in ~/.config/ateam/config.toml; override per project with .ateam/config.toml (ateam init --project).

# safe parallel runs: a branch per task, waits for your review
isolation = "worktree"
merge = "review"

[verify]
command = "npm test"
max_fix_attempts = 2

[agents.codex]
effort   = "high"
fallback = ["claude"]
role     = "Write code, fix bugs, run tests, refactor."

# add any headless CLI
[agents.gemini]
command    = ["gemini", "--yolo", "-p", "{prompt}"]
model_args = ["--model", "{model}"]
role       = "Read large codebases, write docs."

## 09 faq

Frequently asked questions.

Does it cost extra or need API keys?

No. ateam calls the CLIs you already installed and signed in to (Claude Code, Codex, Antigravity, Grok, OpenCode…), so it uses the subscription each CLI already has. ateam sends your data nowhere else.

Which CLIs are supported?

Built in: claude, codex, agy (Antigravity), grok, opencode. Plus any CLI with a headless mode (takes a prompt, prints to stdout) — Gemini CLI, Cursor CLI, Aider… — added from the Agents tab, with templates and a command preview.

Is it safe to let agents edit my code?

Turn on isolation = "worktree" and merge = "review": each task works on its own git branch, never touching your working tree; changes reach your branch only after you review the diff and merge. Agents' shell / network permissions are off by default — enable them in the Safety step of /setup.

How do I make every agent follow project conventions?

Add rules with /rules (e.g. "commit messages in English", "never edit files in dist/"): ateam prepends them to every prompt, so claude, codex, agy, grok, opencode and custom agents all get them. Rules are stored on your machine, not in the repo. Existing AGENTS.md / CLAUDE.md files are still read by the CLIs as usual.

Where is my data?

The task board, logs and pasted images live in the project's .ateam/ (added to .gitignore for you). Global config, to-dos and notes are in ~/.config/ateam/. Everything runs on your machine.

What happens when an agent hits its rate limit?

ateam recognizes each CLI's rate-limit messages, estimates the reset time, rests that agent and moves its tasks to a fallback agent (fallback) — the lead role included. Check status with /usage; rest an agent manually with /cooldown.

Is the web UI safe? Can I open it from another device?

By default ateam web listens on 127.0.0.1 only and rejects unknown Host/Origin headers; files outside the project can't be opened. From your phone: ateam web --tunnel (Cloudflare Tunnel, https) or --host 0.0.0.0 on your LAN — then every request needs a token (scan the QR code printed in the terminal), and --readonly gives view-only access.

Does it run on Windows?

ateam is developed and tested on macOS and Linux (Python 3.9+). On Windows, WSL is the closest option; native Windows hasn't been tested.

Is the UI available in English?

Yes. /lang en in the app (it restarts itself), or ateam lang en / ateam --lang en …. On first run the language follows your system LANG.

Something doesn't work — where do I start?

Run ateam doctor, then ateam log <task number>: the first line shows the agent, model, effort and working directory. Common problems and fixes are in the README's troubleshooting section (Xử lý sự cố).
